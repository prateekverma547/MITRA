# QA Engineer

**Location:** Noida (hybrid, 3 days in office)
**Experience:** 3 to 6 years
**Team:** Quality Engineering

## About the role

You will own quality on one or two client engagements at a time, across web and
mobile. Our work is delivered to a date agreed with a client, so the useful
question is not whether you found bugs but whether the right ones were found
early enough to do something about.

You will write tests, run releases, and be the person who says a build is not
ready when it is not ready.

## What you will do

- Write and own the test plan for a release, including what you have decided not
  to test and why
- Build and maintain automated suites, usually Selenium or Playwright for web and
  Appium for mobile
- Test APIs directly rather than only through the interface
- Run regression before each release, and keep it short enough that it actually
  gets run
- Raise defects that a developer can reproduce from the ticket alone
- Sit in UAT with the client and triage what they find
- Work in the sprint rather than after it, including reviewing stories before
  they are picked up

## What we are looking for

- 3 or more years testing software that shipped to real users
- Automation you have written and maintained yourself, not only run
- A clear account of a bug that reached production, how it got there, and what
  changed afterwards
- Comfort holding a release when the evidence says to, including under pressure
- Enough understanding of the system to test more than the happy path

## Nice to have

- Mobile testing across a device matrix, including on real hardware
- Performance or load testing
- CI experience, wiring suites into a pipeline rather than running them locally
